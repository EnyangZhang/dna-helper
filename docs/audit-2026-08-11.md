# 2026-08-11 Pipeline 全面审计

审计范围为核心状态机的 25 种模式/技能组合。本次审计未发现缺失节点、越界坐标或立即死路。

标记说明：`x` 表示已经修复；未标记的项目仍待处理。其中早期修复来自 Codex 任务 `019feb4b-bb9e-7190-860e-82cc2598da69`。本文件记录审计结论和修复状态，不替代针对运行时画面的回归测试。

## 高优先级

1. [x] 密函驱离可能在同一轮重复释放技能

   原因：密函技能结束后重新进入 `CipherExpelMonitor`，监控仍会识别 Q 未启用状态。若 Q 被关闭、按键未生效或图标未变化，便会再次执行延迟和 E/Q，形成同一副本内循环释放。

   修复：首次连续三帧确认左下角角色血条 HUD 后开始延迟；Q 图标不再参与触发或复核，技能组合结束后仅进入结算监听，下一轮才允许重新检测和释放。

   相关位置：`assets/resource/base/pipeline/RewardConfirm.json`、`assets/resource/base/pipeline/CharacterControl.json`、`README.md`。

2. [x] “挂机”预设同时启用两个长期任务

   原因：预设曾按顺序启用密函和普通任务，但密函无尽本身不会自然结束，因此正常情况下普通任务永远无法开始，用户必须手动关闭其中一个。

   修复：挂机预设现仅启用一个长期任务，避免队列被首个无尽任务永久阻塞。

   相关位置：`assets/resource/tasks/preset/AFK.json`。

3. [x] 非高台和 HUD 等待产生的截图此前没有保留期

   非高台是正常结果，但当前通过 `timeout → on_error` 实现，每次识别为非高台都会保存错误截图；HUD 三帧识别超时也会保存截图。

   审计时已产生 69 张错误截图、约 84.61 MB；整个 `debug` 目录约 115.85 MB。现已增加启动时 14 天保留期和设置页“完全清空日志”，因此不会再无限增长。正常分支仍可能生成错误截图，属于后续可继续优化的诊断噪声。

   相关位置：`assets/resource/base/pipeline/CharacterControl.json`、`tools/mxu-v2.1.3-log-retention.patch`、`dist/DNAHelper/debug/on_error`。

4. [x] `run.py` 已经无法独立运行当前 Pipeline

   原因：`RewardConfirmEntry` 的第一步为自定义动作 `focus_guard_start`，而旧 `run.py` 只加载资源和控制器，不启动 AgentServer，自定义动作不会注册。

   处置：确认该命令行入口已被桌面版替代后，已移除 `run.py`，不再保留错误的独立运行说明。

   相关位置：原 `run.py`、`assets/resource/base/pipeline/RewardConfirm.json`。

## 中优先级

5. [x] 关闭技能时可能错误记录“幽灵轮次”

   原因：普通扼守和普通驱离在关闭技能时曾由任务入口直接执行轮次计数，若用户在“再次进行”结算页启动，会立即记录一轮。

   修复：局外副本轮次统一表示“已完成副本数”，仅在识别到“再次进行”后记录；任务启动、HUD 确认、技能释放和点击“开始挑战”均不计局外副本轮次。局内轮次另行表示同一副本内部进度。扼守/驱离 × 技能开/关的四条路径均已做专项验证。

   相关位置：`assets/resource/base/pipeline/NormalEndlessBoost.json`、`assets/resource/tasks/NormalEndlessBoost.json`、`agent/round_logger.py`。

6. 高台分支等待结束后不重新确认当前页面

   高台或非高台结果在延迟前锁定，延迟结束后直接发送技能。若延迟很长，期间已经结算或玩家手动开启 Q，仍可能发送 E/Q。普通非高台关闭模式会在技能入口先检查结算按钮，高台分支没有这层保护。

   相关位置：`assets/resource/base/pipeline/CharacterControl.json`。

7. 桌面版没有强制检查 1280×720

   模板 ROI 和点击坐标全部按 1280×720 编写。MXU 桌面版只按窗口类名和标题连接，没有尺寸保护；错误分辨率下可能长期识别不到、点击错误位置或空转而无明确报错。

   相关位置：`assets/interface.json`；原 CLI 的尺寸检查已随 `run.py` 移除。

8. 构建过程不是事务式的，失败会留下半成品

   构建脚本先删除现有 `agent`、`maafw`、`resource`，之后才复制新文件。若运行中的程序锁定 DLL，删除会中途失败，输出目录可能已缺少部分文件。审计期间实际发生过 Agent 已清除、随后在锁定的 `DirectML.dll` 处失败的情况。

   相关位置：`build_ui.py`。

9. 窗口恢复失败不会反馈

   窗口恢复结果被忽略；只要游戏输入成功，整个自定义动作就报告成功。此外只保存一个候选窗口，短暂出现的弹窗可能覆盖原窗口，弹窗关闭后会失去恢复目标。

   相关位置：`agent/focus_restore.py`。

## 低优先级及维护问题

10. 所谓无限监听实际最多循环 1000 万次

    多个监控节点设置 `max_hit: 10000000`。按 50ms 计算最短约 5.8 天后耗尽；算上识别时间约为数天到十几天，不是真正无限。

    相关位置：`assets/resource/base/pipeline/NormalEndlessBoost.json`、`assets/resource/base/pipeline/RewardConfirm.json`。

11. 零技能执行也会显示“技能组合结束”

    例如开启“仅高台 E”、识别为非高台、同时关闭 Q 时，实际一个按键都没有发送，但日志仍显示“本次技能组合结束”，容易误判成功。

    相关位置：`assets/resource/base/pipeline/CharacterControl.json`。

12. 校验器覆盖范围不足

    已补充 Pipeline 节点重名、`next` / `on_error` 悬空引用、覆盖目标、保守可达性以及显式 Agent 动态目标检查。但校验器仍不检查每一种最终覆盖组合中的禁用节点死路、点击坐标、ROI 或任意自定义动作参数。因此此前“禁用延迟节点导致任务失败”一类组合问题仍需要专项路径测试。

    相关位置：`tools/validate_project.py`。

13. [x] 存在大量不可达旧节点

    原因：至少二十多个旧节点不属于任何当前模式路径，包括旧普通驱离点击链、旧普通无尽状态机、普通第一页确认链、`Bootstrap` 和已废弃的二次 Q 检测节点。它们虽然不直接影响运行，但会增加后续误接旧逻辑的风险。

    修复：已按全部现有模式、选项覆盖和 Agent 动态调用目标的可达路径并集，删除 25 个确认不可达的旧节点及未导入的 `Bootstrap` 任务文件。校验器现会检查节点重名、悬空 `next` / `on_error` 引用、覆盖目标、Agent 动态目标和不可达节点；当前 64 个 Pipeline 节点全部可达。

14. [x] README 和架构文档明显过期

    原因：文档曾包含默认 1000ms、只实现密函、旧驱离页面顺序和旧技能重复规则等说明，与当前程序不一致。

    修复：README 已按当前 2 个任务、5 种模式、2000ms 默认技能延迟、完成轮次语义、每副本一次技能、运行依赖和已知限制重写；架构文档已同步当前 Pipeline 覆盖、Agent 动态目标、焦点恢复、构建及校验约束。

    相关位置：`README.md`、`docs/architecture.md`。

15. 构建产物并不真正独立

    界面通过系统 PATH 中的 `python` 启动 Agent，并依赖已安装的 `maa` Python 包。换到没有配置 Python 环境的电脑，桌面程序虽可启动，但 Agent 自定义动作无法使用。

    相关位置：`assets/interface.json`。

## 结论与优先顺序

普通无尽、普通扼守和普通驱离的当前主路径已连通；普通扼守和普通驱离的轮次语义已改为“结算完成才计数”。下一步应依次处理：错误截图膨胀、挂机预设阻塞、高台延迟后的页面保护，以及桌面版分辨率校验。
